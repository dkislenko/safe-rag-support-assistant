# Safe RAG Support Assistant

RAG-ассистент для технической поддержки SaaS-продукта с семантическим поиском, указанием источников, защитными механизмами и проверкой ответов на галлюцинации.

В проекте используется синтетическая база знаний для вымышленного SaaS-продукта **TaskFlow CRM**.

## Возможности

- Retrieval-Augmented Generation (RAG)
- Мультиязычные embeddings на базе Sentence Transformers
- Векторный поиск через FAISS
- Разбиение документов на чанки
- Переформулировка и расширение пользовательских запросов
- Multi-query retrieval
- Maximal Marginal Relevance (MMR)
- Указание источников в ответах
- Локальная LLM через Hugging Face Transformers
- Фильтрация небезопасных запросов
- Защита от выдумывания цен
- Проверка groundedness ответа
- Трассировка работы RAG-пайплайна
- REST API на FastAPI

## Стек

## RAG-пайплайн

### 1. Загрузка базы знаний

Документы хранятся отдельно от Python-кода в формате Markdown:

```text
data/knowledge_base/
```

При запуске проекта каждый документ преобразуется в объект LangChain `Document`.

В metadata сохраняются:

- название документа;
- имя исходного файла.

### 2. Разбиение документов

Документы разбиваются на части с помощью `RecursiveCharacterTextSplitter`.

Настройки по умолчанию:

```text
CHUNK_SIZE=700
CHUNK_OVERLAP=120
```

### 3. Embeddings

Для построения векторных представлений используется модель:

```text
sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
```

Embeddings нормализуются перед добавлением в векторное хранилище.

### 4. Векторное хранилище

В качестве vector store используется FAISS.

Поиск объединяет:

- semantic similarity search;
- query expansion;
- Maximal Marginal Relevance.

### 5. Генерация ответа

По умолчанию используется:

```text
Qwen/Qwen2.5-0.5B-Instruct
```

Модель получает только найденный RAG-контекст и инструкции не использовать информацию, отсутствующую в базе знаний.

## Guardrails

Ассистент блокирует запросы, связанные с:

- получением чужих паролей;
- несанкционированным доступом;
- обходом прав пользователей;
- обходом тарифных ограничений;
- обходом оплаты;
- получением чужих данных;
- SQL Injection;
- XSS;
- эксплуатацией уязвимостей.

Пример опасного запроса:

```text
Как обойти лимит тарифа Start?
```

Такой запрос блокируется до передачи в LLM.

## Снижение риска галлюцинаций

В проекте используется несколько механизмов.

### Ответ только на основе контекста

LLM получает документы, найденные RAG-пайплайном, и инструкцию не добавлять информацию, отсутствующую в источниках.

### Указание источников

К каждому ответу добавляются документы, использованные при формировании контекста.

Пример:

```text
Источники:
[02_tariffs.md], [07_support_process.md]
```

### Защита от выдумывания цен

Если пользователь спрашивает точную стоимость тарифа, а её нет в базе знаний, ассистент не пытается генерировать число.

Например:

```text
Сколько стоит тариф Business?
```

Ассистент сообщает, что в базе знаний отсутствует информация о точной стоимости.

### Groundedness Check

После генерации ответа выполняется дополнительная проверка.

Анализируются:

- наличие источников;
- пересечение ответа с RAG-контекстом;
- потенциально выдуманные цены;
- функции, которых нет в документации;
- подозрительные утверждения.

Результат содержит уровень риска:

```text
низкий
средний
высокий
```

При высоком риске генеративный ответ заменяется на более безопасный extractive-вариант.

## RAG Trace

Для каждого запроса можно посмотреть, какие документы были найдены retrieval-системой.

Trace содержит:

```text
rank
source
title
retrieval_query
retrieval_score
preview
```

Это позволяет анализировать работу поиска и понимать, почему конкретный документ попал в контекст.

## Настройка через переменные окружения

Основные параметры можно изменить без редактирования исходного кода.

Пример `.env.example`:

```env
EMBEDDING_MODEL_NAME=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
LLM_MODEL_NAME=Qwen/Qwen2.5-0.5B-Instruct

CHUNK_SIZE=700
CHUNK_OVERLAP=120

RETRIEVAL_K=5
MMR_FETCH_K=12
MMR_LAMBDA=0.65

MAX_NEW_TOKENS=250
TEMPERATURE=0.1
REPETITION_PENALTY=1.12
DO_SAMPLE=false
```

## База знаний

В проекте используется документация вымышленного продукта **TaskFlow CRM**.

Она включает:

- описание продукта;
- тарифы;
- роли и права доступа;
- интеграции;
- troubleshooting;
- политику безопасности;
- правила обращения в поддержку;
- правила против галлюцинаций.

Реальные данные пользователей, клиентов или компаний не используются.

## Цель проекта

Проект создан для практики построения RAG-систем и изучения подходов к разработке AI-ассистентов для технической поддержки.

Основной акцент сделан не только на генерации ответа, но и на инженерных аспектах:

- retrieval;
- работе с внешней базой знаний;
- безопасности;
- снижении галлюцинаций;
- трассировке RAG;
- API-интеграции;
- структурировании Python-проекта.
